# hdmi_rx — HDMI データアイランド受信 (音声 / AVI InfoFrame) と ΔΣ DAC

`rtl/dvi_in` が取り出すデータアイランドの TERC4 ニブルから HDMI パケットを組み立て、2ch LPCM 音声を
再生して 1 bit ΔΣ で GPIO に出す。すべてピクセル (TMDS キャラクタ) クロック領域で動く。

```
dvi_in (o_island / o_island_first / o_terc4 / o_terc4_err)
  → hdmi_packet_rx : 32 ワード = 1 パケット、BCH(32,24) / BCH(64,56) の検査
  → hdmi_audio_rx  : ACR (N / CTS)、Audio Sample (layout 0)、AVI InfoFrame
                     FIFO (512 x {L[23:6], R[23:6]}、BSRAM 1 個) + NCO + 直線補間
  → delta_sigma_dac: 2 次 1 bit ΔΣ (L / R)
rgb_range_expand   : AVI がリミテッドレンジ (16–235) のとき RGB をフルレンジに伸ばす
```

| モジュール | 内容 |
|---|---|
| `hdmi_packet_rx` | アイランド先頭のガードバンド 2 ワードを飛ばし、32 ワードごとにヘッダ 24 bit + 4 サブパケット × 56 bit と各パリティの一致を出す。末尾のガードバンドで始まった不完全なパケットは捨てる |
| `hdmi_audio_rx` | 再生レート fs = f_TMDS × N / (128 × CTS)。P = 2^33 × N / CTS を直列除算器 (53 クロック) で求め、40 bit の NCO が 1 周するごとに FIFO から 1 サンプル取り出す。送り側の音声クロックに追従するので音声 PLL は要らない |
| `delta_sigma_dac` | Boser-Wooley 型 2 次 (積分器ゲイン 1/2、雑音伝達関数 (1 − z⁻¹)²)。入力は 3/4 に縮めて安定させる |
| `rgb_range_expand` | out = clamp((in − 16) × 298 / 256)、1 クロック遅延 |

## 補間が要る理由

サンプルを次のサンプルまで保持するだけだと、切り換え時刻が DAC の更新周期 (6.19 MHz なら 161 ns) に
丸められる。これは信号の傾きに比例するジッタ誤差で、10 kHz のトーンでは帯域内 SNR が約 50 dB に落ちる
(1 kHz で約 70 dB)。NCO の位相の上位 16 bit を小数位置として前後 2 サンプルを直線補間すると、この誤差が消えて
88 dB になる (数値モデル、下表)。新しいサンプルが `cur` に入るのは NCO が 1 周してから 2 クロック後なので、
位相も 2 クロック遅らせて揃える (揃えないと、その間の更新で 1 サンプル分跳ぶ: 実測で 68 dB に落ちた)。

| 条件 (DAC 6.1875 MHz、20 Hz–20 kHz) | SNR |
|---|---|
| 保持のみ、1 kHz フルスケール | 70.8 dB |
| 保持のみ、10 kHz フルスケール | 50.9 dB |
| 直線補間、1 kHz / 10 kHz フルスケール | 88.0 / 88.1 dB |
| 直線補間、1 kHz −60 dBFS | 33.0 dB (ノイズフロア約 −93 dBFS) |

## 使うパケット

| HB0 | パケット | 使う内容 |
|---|---|---|
| 0x01 | Audio Clock Regeneration | CTS = {SB1[3:0], SB2, SB3}、N = {SB4[3:0], SB5, SB6} |
| 0x02 | Audio Sample | HB1[3:0] = サンプルの有無、HB1[4] = layout (0 のみ対応)、HB2[3:0] = flat。サブパケット i の SB0–2 = L、SB3–5 = R |
| 0x82 | AVI InfoFrame | チェックサム確認後、Y (PB1[6:5])、Q (PB3[3:2])、VIC (PB4)。RGB で Q = 1、または Q = 0 かつ VIC ≠ 0 (CE フォーマット) ならリミテッドレンジ |

ヘッダのパリティ誤りは `o_hdr_err`、使うパケットのサブパケットの誤りは `o_sub_err` で数え、そのパケットは使わない。

## シミュレーション

`make -C test`: 200 × 40 ワードのラスタの水平ブランキングに毎ライン 1 つのデータアイランド (AVI をフレームごと、
ACR を 16 ラインごと、溜まった音声サンプル) を載せた HDMI ワード列を `dvi_in` に入れ、音声は
fs = f × 6144 / (128 × 74250) の 24 bit 正弦波 (L 1 kHz、R 3 kHz)。

- FIFO から出た全サンプルが送ったものと順番どおり一致する (8134 サンプル)
- N / CTS、AVI のレンジ (リミテッド → フル) の切り換え、VIC
- わざと入れたヘッダ / サブパケットのビット誤りがちょうどその数だけ数えられる、TERC4 異常なし
- FIFO のアンダーラン / オーバーランなし
- L の DAC ビット列 2^20 個を `analyze.py` で解析: 1 kHz、帯域内 SNR 88.2 dB (合格 80 dB 以上)
