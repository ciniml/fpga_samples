# csi2 — MIPI CSI-2 受信 (ソフト D-PHY, Veryl)

FPGA の汎用 LVDS 入力だけで Raspberry Pi カメラ (2 レーン CSI-2) を受けるための受信コア。
D-PHY の LP 受信器 (1.2V 単線コンパレータ) も PLL によるクロック再生も使わない。

```
 clock / D0 / D1 のオーバーサンプル (OSIDES32: 32 サンプル/ワード, ~4 Gsps)
   └► Csi2EdgeSampler   クロックレーンのエッジ位置でデータを拾う (DDR: 1 エッジ = 1 ビット)
   └► Csi2LaneAligner×2 ギアボックス → HS-zero + 0xB8 の SoT 検索 → バイト
   └► Csi2LaneMerge     2 レーン → 16bit ビート (レーン間スキュー吸収)
   └► Csi2Packet        ヘッダ ECC (1bit 訂正), ショート/ロング, CRC16
```

## なぜこの構成か

- Raspberry Pi カメラ (IMX219 / OV5647) は**非連続クロック**: ライン間でもクロックレーンが
  LP-11 に戻る (Pi の device tree は `clock-noncontinuous`、IMX219 データシート Fig. 21)。
  クロックレーンを PLL で再生する方式も、HCLK に直接入れて IDES のクロックにする方式も
  LP 期間に破綻する。全レーンを自前の自走クロックでオーバーサンプリングし、クロックレーンの
  遷移をデータのサンプル位置に使えば、クロックの有無は「ビットが来ない」だけになる。
- D-PHY のクロックはデータアイの中央 (DDR, 90°) にあるので、遷移と同じサンプル時刻の
  データが最適点。レーン間スキューは `i_ofs[l]` (サンプル単位 −8..+7) で補正する。
- クロックの 3 サンプル多数決で、交差付近の 1 サンプルのノイズ (2 エッジ = 2 ビット混入) を除く。

## LP 状態の扱い (LP 受信器なし)

差動受信器だけなので LP-11 / LP-00 (差動 0V) はノイズ、LP-01 は「0 の連続」に見える。

- SoT は「ZEROS (既定 24) ビットの 0 + 0xB8」。THS-ZERO は ≥105ns+6UI なので本物は必ず満たす
- **偽 SoT**: LP-01 (0 の連続) の直後の LP-00 ノイズに 0xB8 が現れると成立する
  (シミュレーションで約 1 割のバースト)。パケット解析がヘッダを受理 (ECC シンドローム 0) する
  まではアライナが検索を続け、後から来た本物の同期で仕切り直す (`i_lock`)。
  レーン結合は「先頭バイト」でそのレーンの FIFO を捨てる
- 訂正できたヘッダでは `o_lock` を立てない: ランダムなヘッダの約半分は「1bit 訂正可能」に見える

## テスト (`veryl test`、または Verilator 直)

`test/csi2_rx_body.sv` が D-PHY 送信モデル (LP-01→LP-00→HS-0→同期→データ→トレイル、
非連続クロックの TCLK-PRE/POST、LP のチャタリング、ppm、ジッタ、レーンスキュー) を
4 Gsps でサンプルし、FS / 埋め込み / RAW10 行 / 奇数長ロング / FE を順番通り・CRC 一致で
受けることを確認する。

| テスト | 条件 | 結果 |
|---|---|---|
| csi2_pkg_t | ECC / CRC を CSI-2 仕様の例と照合 (0x3F, 0x00F0, 0xE569) | PASS |
| csi2_456 / _q | 456 Mbps、LP チャタリング有/無 | 20/20 |
| csi2_456_skew | +300 ppm、ジッタ 0.1 UI、レーン 1 が 0.6 ns 遅れ | 20/20 |
| csi2_912 | 912 Mbps (4.4 サンプル/UI)、ジッタ 0.05 UI | 20/20 |
| csi2_cont | 連続クロック | 20/20 |
| csi2_trim | レーン 1 が 1.5 ns 遅れ、`i_ofs[1]` = 14 で補正 | 20/20 |
| csi2_912_long | 15 フレーム (150 パケット)、+300 ppm | 150/150 |

## 制約・未対応

- 2 レーン固定 (15 ピン FFC のカメラは全て 2 レーン)、VC は通すだけ
- 1 バースト 1 パケット前提 (IMX219 はパケットごとに LP に戻る)。同一バースト内の連続
  パケットは 2 個目を取りこぼす
- MAXB = 8: 1 ワード (32 サンプル) に 8 エッジまで = 4 Gsps で ~1 Gbps/レーンが上限
- ボード側 (OSIDES32 ラッパ、計測、ホストツール) は `eda/csi_capture`
