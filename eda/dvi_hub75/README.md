# dvi_hub75 — DVI / HDMI 入力 (720p60) → HUB75 LED マトリクス

Tang Primer 25K で受信した 720p60 の左上 `W × H` 画素を、そのまま (等倍で) 64x64 HUB75 パネルに表示する。
パネル構成は 64x64 / 128x64 / 64x128 / 128x128 (`make PANEL=<W>x<H>`、既定 128x128)。
HDMI の音声 (2ch LPCM) も受けて、1 bit ΔΣ DAC で GPIO 2 本から出す (`rtl/hdmi_rx`)。

```
HDMI/DVI source ─► pmod0 (Pmod DVI) ─► dvi_in_phy (pclk 74.25 MHz, eda/dvi_capture と共通)
   DDC / HPD  ◄─► 40 ピンヘッダ (F1 / F2 / A1)             │ RGB24 / DE / VSYNC     │ データアイランド
                                           rgb_range_expand (AVI)       hdmi_packet_rx → hdmi_audio_rx
                                                           │              → delta_sigma_dac ×2 → D1 / E3 → RC LPF
                                    crop_to_hub75: 左上 W×H を切り出し、チェーン上のアドレスへ
                                                           │ {flip, addr, RGB555}
                                                async FIFO (pclk → 50 MHz)
                                                           ▼
                                    Hub75 (rtl/hub75): ダブルバッファ VRAM、6 bit BCM
                                                           ▼
                                pmod1 + pmod2 (HUB75 Pmod ベースボード) ─► パネル
```

## ビルドの変種

| 変数 | 値 | 内容 |
|---|---|---|
| `PANEL` | `64x64` / `128x64` / `64x128` / `128x128` (既定) | 表示サイズ |
| `BITS` | `5` / `6` (既定) | 色あたりの BCM ビットプレーン数 |
| `HUB75_CLKDIV` | `0` (既定) / `1` | HUB75 のシフトクロック分周。CLK = 50 MHz / (2 × (N + 1) + `HUB75_CLKLOW`)、`HUB75_CLKDIV=1 HUB75_CLKLOW=0` で 12.5 MHz |
| `GAMMA` | 例 `2.2` (既定は恒等) | 色テーブルの初期値 (リセット後と `i`) をガンマ `<g>` にする (`gen_lut_init.py`、表示ビット数で丸め)。UART なしで動かす展示用 |
| `HDMI_AUDIO` | `1` (既定) / `0` | 1: HDMI 用 EDID (CEA-861 拡張、2ch LPCM) で音声を受ける。0: DVI 専用 EDID (音声なし、レンジ変換なし) |
| `HUB75_CLKLOW` | `0` / `1` (既定) | 1 画素あたり CLK Low を延ばすティック数。既定の組み合わせで 16.7 MHz (Low 40 ns / High 20 ns) |

128x128 の比較 (リフレッシュはシミュレーションで測った 1 走査の長さ、合成は Gowin 1.9.12):

| 構成 | リフレッシュ | BSRAM | タイミング |
|---|---|---|---|
| 5 bit、12.5 MHz (`BITS=5 HUB75_CLKDIV=1 HUB75_CLKLOW=0`) | 254 Hz | 37/56 | 違反なし |
| 6 bit、12.5 MHz (`HUB75_CLKDIV=1 HUB75_CLKLOW=0`) | 190 Hz | 41/56 | 違反なし |
| 6 bit、16.7 MHz (既定) | 234 Hz | 41/56 | 違反なし (実機で正常) |
| 6 bit、25 MHz (`HUB75_CLKLOW=0`) | 305 Hz | 41/56 | 違反なし (実機では B2 を取りこぼす) |

ホスト側のガンマテーブルは表示ビット数で丸める (`loopctl.py gamma 2.2` は既定で 6 bit、5 bit 版では `loopctl.py gamma 2.2 rgb 5`)。
25 MHz のシフトクロックは実機 (64x64 × 4 枚のチェーン) では通らなかった。上段パネルの行 32–63 で B2 が
まったく出ず (黄色っぽく見える)、12.5 MHz に戻すと正常に表示された (2026-10-01)。
チェーンの途中で B2 の波形がなまって、それより先のパネルで取りこぼしていると見られる。
遠い側のパネルのデータは上流パネルのドライバ IC が CLK に合わせて出し直したものなので、FPGA 側の
ドライブ能力や出力遅延では直らず、CLK の周期を延ばすしかない。1 画素を Low 2 + High 1 クロックにした
16.7 MHz (`HUB75_CLKLOW=1`) では正常に表示された (234 Hz)。Low 側を延ばすのは、上流のドライバが CLK の
立ち下がりで出力を変える品種でも次の立ち上がりまでの時間を稼げるようにするため。

## パネルの配置

64x64 パネル (1/32 スキャン、A〜E) は、パネル内の行 0–31 が R1G1B1、行 32–63 が R2G2B2 (同じ行アドレス)。
高さ 128 の構成は電気的には 1 本のチェーンで、下半分 (y 64–127) の 64 行が上半分の右側につながる
(128x128 = 256x64)。表示座標 (x, y) → VRAM アドレス:

```
seg     = y / 64            下半分なら 1
yy      = y % 64
half    = yy / 32           0: R1G1B1, 1: R2G2B2
scan    = yy % 32           行アドレス A..E
chain_x = seg * W + x       (CHAIN_REVERSE パラメータで反転)
addr    = {half, scan, chain_x}
```

チェーン上の向き (最初にシフトした画素が左端に来るか右端に来るか) は実機で確認する。左右が逆なら
`crop_to_hub75` の `CHAIN_REVERSE` を 1 にする。

## バッファの方式

1 フレーム分のフレームバッファ (ダブルバッファ) を持つ。HUB75 は BCM のビットプレーンごとに同じ行を送り直しながら
入力と無関係に数百 Hz で走査し続けるうえ、1 回のシフトに表示行 r / r+32 / r+64 / r+96 が同時に要るので、
上半分だけを FIFO に溜める方式では足りない (待ち量がほぼ 1 フレームになる)。

- 128x128 × RGB555 × 2 面 = BSRAM 32 個 (全体で 35/56)。64x64 は 11/56
- 書き込みは切り出し範囲の最終行のあとに FLIP を送り、表示側はパネルのフレーム境界で面を切り替える (ティアリングなし)
- 前回の FLIP がまだ消化されていないうちに次のフレームが来たら、そのフレームは書かずに捨てる

## 色テーブル (ガンマ補正 / ホワイトバランス)

`crop_to_hub75` は R / G / B それぞれに 256 エントリ × 8 bit のテーブルを持ち、入力の 8 bit 値で引いた結果の
上位 `COMPONENT_BITS` (6) bit を表示する。デュアルクロック BSRAM (書き込みは 50 MHz、読み出しはピクセルクロック)。

- 既定 (リセット後) は恒等 = ガンマ 1.0 (入力の上位ビットをそのまま表示、テーブルなしと同じ)
- UART から更新: `G<mask><512 桁の 16 進>` (mask = bit0 R / bit1 G / bit2 B、256 バイトをエントリ 0 から)、
  `i` で恒等に戻す。行の出力中でも取りこぼさない
- ホスト: `loopctl.py gamma 2.2` (全チャネル)、`loopctl.py gamma 2.0 r` (R だけ)、`loopctl.py gamma identity`。
  値は `round((in/255)^g × 63) << 2` (6 bit 表示に合わせて丸めた 8 bit 値)
- ガンマ 2.2 にすると、6 bit 表示では入力 29 未満、5 bit 表示では入力 40 未満が 0 になる

## ピン

| 信号 | ピン |
|---|---|
| DVI RX | pmod0 (H5 / H8 / G7 / F5、LVDS25 + 内蔵終端 + CTLE HIGH) |
| DDC SCL / SDA / HPD | 40 ピンヘッダ 15 (F1) / 16 (F2) / 17 (A1)。18 (E1) は CEC 用に予約。11 = +5V、12 = GND |
| HUB75 | pmod1 + pmod2 (`pins.cst`)。ベースボードのモジュール側 pmod0 (RGB / E / B) が pmod2 (G11 側)、pmod1 (LAT / CLK / OE / A / C / D) が pmod1 (A11 側) |
| UART | C3 (TX) / B3 (RX)、115200 8N1 |
| 状態出力 | B2 = ワードロック、C2 = デコードエラー (40 ピンヘッダ 14 / 13) |
| S1 (H10) | HPD を 200 ms 下げて EDID を読み直させる |
| 音声 DAC L / R | 40 ピンヘッダ 19 (D1) / 20 (E3)、LVCMOS33 DRIVE=8 |

DDC はソース側で 5 V にプルアップされるので、レベル変換 (PCA9306 等) かクランプを入れる。

## 音声

`HDMI_AUDIO=1` (既定) では EDID に CEA-861 拡張 (2ch LPCM 32 / 44.1 / 48 kHz、HDMI VSDB、RGB レンジ選択可) を
載せるので、ソースは HDMI で送り、データアイランドに音声を載せる。再生レートは ACR の N / CTS から
fs = f_TMDS × N / (128 × CTS) で再現する (詳細は `rtl/hdmi_rx/README.md`)。

- ΔΣ DAC は 2 次 1 bit、更新は 74.25 MHz / 12 = 6.1875 MHz。数値モデルとシミュレーションでの帯域内
  (20 Hz–20 kHz) SNR は 88 dB (フルスケール正弦波)。実際はピンの電源ノイズとエッジの非対称で決まる
- AVI InfoFrame がリミテッドレンジ (Q = 1、または Q = 0 で CE フォーマット) なら RGB をフルレンジに伸ばしてから
  色テーブルに入れる。VCDB で QS = 1 を宣言しているので、多くのソースはフルレンジで送る
- 実機 (ノート PC、2026-10-01): HDMI として認識、N = 11648 / CTS = 140625 (fs = 48000.4 Hz)、パケットの
  パリティ誤り 0、FIFO のアンダーラン / オーバーランなし、フルレンジ

### LPF (チャネルごと)

```
D1 / E3 ─ R1 1kΩ ─┬─ R2 10kΩ ─┬─ C3 1µF ─→ 出力 (入力インピーダンス 47kΩ 以上のアンプ / ライン入力)
                  C1 3.3nF     C2 330pF
                  │            │
                 GND          GND
```

- 1 段目・2 段目ともカットオフ約 48 kHz。2 段目の R を 1 段目の 10 倍にして段間の干渉を減らす
- 周波数特性 (ピンの出力インピーダンス 30 Ω 込みの計算): −3 dB が 28.5 kHz、20 kHz で −1.6 dB、100 kHz で −15 dB、
  1 MHz で −53 dB、6.19 MHz で −85 dB
- 20 kHz まで平坦にするなら C1 = 2.2 nF、C2 = 220 pF (−3 dB 約 43 kHz、20 kHz で −0.7 dB、6.19 MHz で約 −77 dB)
- C3 は直流カット (出力の中心は 1.65 V)。47 kΩ 負荷で低域 −3 dB は 3.4 Hz
- フルスケール正弦波で約 1.1 Vrms (ラインレベル相当)。出力インピーダンスが約 10 kΩ なのでヘッドホンは直接駆動できない
- さらに良くするなら、静かな電源の 74LVC1G74 などでピンの出力を打ち直してから LPF に入れる (I/O 電源のノイズが
  そのまま出力に乗るため)

## UART

`eda/dvi_capture` と同じ診断 (`eda/dvi_loopback/host/loopctl.py`)。X = {DDC SCL 立ち下がり回数 (14), SCL, SDA, EDID 読み出しバイト数 (16)}、
Y = {HPD (1), FIFO オーバーフロー回数 (15), 捨てたフレーム数 (8), DDC オフセット (8)}。
Z0 = {パケット数 (16), ヘッダのパリティ誤り (8), サブパケットのパリティ誤り (8)}、
Z1 = {N (20), 音声 FIFO の水位 / 2 (9), リミテッドレンジ, 再生中, TERC4 異常あり}、
Z2 = {CTS (20), アンダーラン (6), オーバーラン (6)}。`loopctl.py audio` で解読して fs も出す。

## シミュレーション

`make sim` (`test/`): 映像源 → `crop_to_hub75` → async FIFO → `Hub75` → HUB75 パネルモデル。パネルモデルは
CLK 立ち上がりでシフト、LAT でラッチ、OE が Low の間 (ビット × 期間) を行アドレスの画素に積算し、
1 回の走査で表示される値を全画素について期待値と比べる。パネル構成・ビット数・シフトクロックの 8 構成それぞれで、
2 つの絵を順に表示して全画素一致 (途中で混ざらない) を確認する。
あわせて「LAT が High の間に CLK が立ち上がらない」「OE 点灯中に LAT / CLK が動かない」も検査する
(エッジトリガ / 透過型のどちらのラッチでも同じ表示になる条件)。行のシフト中の CLK の Low / High 幅と
データのセットアップ時間 (データ変化 → CLK 立ち上がり) が設定どおりかも測る。色テーブルは R 反転 / G ガンマ 2.2 を
書き込んで全画素がテーブルどおりになること、`init` で恒等に戻ることを確認する。
UART の `G` / `i` の解析は `eda/dvi_loopback` の `make sim` で確認している。
