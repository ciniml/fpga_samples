# dvi_hub75 — DVI / HDMI 入力 (720p60) → HUB75 LED マトリクス

Tang Primer 25K で受信した 720p60 の左上 `W × H` 画素を、そのまま (等倍で) 64x64 HUB75 パネルに表示する。
パネル構成は 64x64 / 128x64 / 64x128 / 128x128 (`make PANEL=<W>x<H>`、既定 128x128)。

```
HDMI/DVI source ─► pmod0 (Pmod DVI) ─► dvi_in_phy (pclk 74.25 MHz, eda/dvi_capture と共通)
   DDC / HPD  ◄─► 40 ピンヘッダ (F1 / F2 / A1)             │ RGB24 / DE / VSYNC
                                    crop_to_hub75: 左上 W×H を切り出し、チェーン上のアドレスへ
                                                           │ {flip, addr, RGB555}
                                                async FIFO (pclk → 50 MHz)
                                                           ▼
                                    Hub75 (rtl/hub75): ダブルバッファ VRAM、5 bit BCM
                                                           ▼
                                pmod1 + pmod2 (HUB75 Pmod ベースボード) ─► パネル
```

## パネルの配置

64x64 パネル (1/32 スキャン、A〜E) は、パネル内の行 0–31 が R1G1B1、行 32–63 が R2G2B2 (同じ行アドレス)。
高さ 128 の構成は電気的には 1 本のチェーンで、下半分 (y 64–127) の 64 行が上半分の右側につながる
(128x128 = 256x64)。表示座標 (x, y) → VRAM アドレス:

```
seg     = y / 64            下半分なら 1
yy      = y % 64
half    = yy / 32           0: R1G1B1, 1: R2G2B2
scan    = yy % 32           行アドレス A..E
chain_x = seg * W + x       (CHAIN_REVERSE パラメータで反転)
addr    = {half, scan, chain_x}
```

チェーン上の向き (最初にシフトした画素が左端に来るか右端に来るか) は実機で確認する。左右が逆なら
`crop_to_hub75` の `CHAIN_REVERSE` を 1 にする。

## バッファの方式

1 フレーム分のフレームバッファ (ダブルバッファ) を持つ。HUB75 は BCM のビットプレーンごとに同じ行を送り直しながら
入力と無関係に数百 Hz で走査し続けるうえ、1 回のシフトに表示行 r / r+32 / r+64 / r+96 が同時に要るので、
上半分だけを FIFO に溜める方式では足りない (待ち量がほぼ 1 フレームになる)。

- 128x128 × RGB555 × 2 面 = BSRAM 32 個 (全体で 35/56)。64x64 は 11/56
- 書き込みは切り出し範囲の最終行のあとに FLIP を送り、表示側はパネルのフレーム境界で面を切り替える (ティアリングなし)
- 前回の FLIP がまだ消化されていないうちに次のフレームが来たら、そのフレームは書かずに捨てる

## ピン

| 信号 | ピン |
|---|---|
| DVI RX | pmod0 (H5 / H8 / G7 / F5、LVDS25 + 内蔵終端 + CTLE HIGH) |
| DDC SCL / SDA / HPD | 40 ピンヘッダ 15 (F1) / 16 (F2) / 17 (A1)。18 (E1) は CEC 用に予約。11 = +5V、12 = GND |
| HUB75 | pmod1 + pmod2 (`pins.cst`) |
| UART | C3 (TX) / B3 (RX)、115200 8N1 |
| 状態出力 | B2 = ワードロック、C2 = デコードエラー (40 ピンヘッダ 14 / 13) |
| S1 (H10) | HPD を 200 ms 下げて EDID を読み直させる |

DDC はソース側で 5 V にプルアップされるので、レベル変換 (PCA9306 等) かクランプを入れる。

## UART

`eda/dvi_capture` と同じ診断 (`eda/dvi_loopback/host/loopctl.py`)。X = EDID 読み出しバイト数、
Y = {HPD (1), FIFO オーバーフロー回数 (15), 捨てたフレーム数 (8), DDC オフセット (8)}。

## シミュレーション

`make sim` (`test/`): 映像源 → `crop_to_hub75` → async FIFO → `Hub75` → HUB75 パネルモデル。パネルモデルは
CLK 立ち上がりでシフト、LAT でラッチ、OE が Low の間 (ビット × 期間) を行アドレスの画素に積算し、
1 回の走査で表示される 5 bit 値を全画素について期待値と比べる。4 通りのパネル構成それぞれで、
2 つの絵を順に表示して全画素一致 (途中で混ざらない) を確認する。
あわせて「LAT が High の間に CLK が立ち上がらない」「OE 点灯中に LAT / CLK が動かない」も検査する
(エッジトリガ / 透過型のどちらのラッチでも同じ表示になる条件)。
