展示作品紹介 — FPGA で作る HDMI 受信機と LED マトリクス表示

HDMI の映像と音声を FPGA で受けて、128×128 の LED パネルに映す

Tang Primer 25K で HDMI 受信機を自作。PC からは普通のモニタに見え、画面左上 128×128 がそのまま LED に、音声は ΔΣ DAC から。
HDMI 受信 IC も高速トランシーバも使わず、FPGA の汎用 I/O で 742.5 Mbps の TMDS 信号を直接受信。EDID 応答・映像の復号・LED の駆動・音声の再生まで、すべて RTL で実装した。

HUB75 とは — LED マトリクスパネルで広く使われる信号形式。パネルにはシフトレジスタと行の選択しかなく、明るさを変える機能はない。1 行分の RGB を CLK で送り込んで LAT でラッチし、行アドレス(A〜E)を切り替えて 1/32 ずつ点灯する。中間の明るさは、駆動側が高速に描き換えて点灯時間で作る。
難しいところ
HDMI を汎用 I/O で受ける720p で 1 レーン 742.5 Mbps。SerDes なしで、IODELAY による位相合わせ、1:10 のデシリアライズ、ワード境界の検出を自前で行う。
パネルには階調がない点灯か消灯かしかないパネルで 26 万色を出すため、ビットごとに点灯時間を倍々に変える BCM 駆動で、全面を毎秒 234 回描き換える。
60 Hz の入力と 234 Hz の表示入力と無関係に走査を続けるパネル側へ、ダブルバッファでフレームを渡し、走査の切れ目で切り替えてティアリングを防ぐ。

システム構成

作ったもの

  • PC から普通の HDMI モニタとして認識される受信機(EDID・DDC・HPD も自作)
  • 画面の左上 128×128 をそのままの画素で 64×64 パネル 4 枚に表示
  • HDMI の音声を取り出し、GPIO 1 本と RC フィルタの ΔΣ DAC で再生
  • USB シリアルでの診断(受信誤り・位相スキャン・音声状態)とガンマの書き換え
  • 展示用ツール: 動画の 128×128 変換、FPGA 側の画面を EDID で探して全画面再生、キー 1 つで切り替え

主要機能

映像受信
TMDS 3 レーンを IODELAY + IDES10 で受信。制御シンボルでワード境界を自動検出し、レーンごとに位相を微調整。DVI / HDMI 両対応(プリアンブル・ガードバンド判定)
EDID
DDC(I²C)ターゲットと HPD 制御。CEA-861 拡張で 2ch LPCM 音声と RGB レンジ選択を宣言
LED 駆動
ダブルバッファ VRAM、6 bit BCM、色ごとのガンマテーブル(256 段)、AVI InfoFrame によるリミテッドレンジ補正
音声
BCH で誤りを検出、N / CTS からサンプルレートを NCO で再現、直線補間 + 2 次 ΔΣ 変調
検証
Verilator: パネルを模したモデルで全画素の表示値と CLK / LAT / OE の規則、HDMI 音声は全サンプル一致と SNR 解析

こだわり・見どころ

  • 専用 IC なしで HDMI 受信アイの中心を位相スキャンで探索。1080p ではレーンごとに最適位相がずれ、個別トリムでビットパーフェクトに
  • チェーンの遠端で起きる取りこぼし25 MHz では遠い側のパネルで下半分の青が欠けた。上流パネルが中継する信号の問題で、CLK の Low を延ばした 16.7 MHz で解決
  • 音声のジッタ対策サンプルを保持するだけだと 10 kHz で SNR 50 dB 程度。NCO の位相で直線補間して 88 dB に(シミュレーション)
  • 合成ツールの落とし穴色ごとのガンマ RAM が 1 個にまとめられて白黒になる問題を、ネットリストから突き止めて回避
